## 二、本轮关键发现：`Robin` 被误译成「知更鸟」

### 2.1 现象

第 5 轮运行时审计发现：

```
NPC_CN_NAME("Robin") -> "知更鸟"    ❌ 应该是「罗宾」
```

### 2.2 根因

上一轮我给 `makeFn`（第 4 层包装）加的**类型表直查兜底**，查表顺序是：

```js
var _keys0 = ["NPCTypeList_cn_name", "NPCTitleList_cn_name"];
```

而**物种表** `NPCTypeList_cn_name` 里有一条 `robin,知更鸟`（知更鸟是一种鸟）。

`Robin`（人名）命中物种表的 `robin` → 返回「知更鸟」，把**人名翻译盖掉了**。

### 2.3 修复

把**名字表**提到查表顺序**第一位**：

```js
var _keys0 = ["NPCNameList_cn_name", "NPCTitleList_cn_name", "NPCTypeList_cn_name"];
```

**修后实测**：

| 查询 | 修复前 | 修复后 |
|---|---|---|
| Robin | 知更鸟 ❌ | **罗宾** ✅ |
| slim plantgirl | 纤细植物娘 | 纤细植物娘 |
| thick dog | 丰腴狗 | 丰腴狗 |

### 2.4 教训

**「直查类型表」这个兜底有副作用**：多义词（`robin` 既是人名又是鸟名）会被物种表抢先。**必须先查名字表**。这正是「修复引入新问题」的典型案例——本轮第 5 轮专门做运行时审计就是为了抓这类回归。
