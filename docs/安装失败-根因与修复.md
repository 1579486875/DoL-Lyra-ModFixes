# 安装失败根因（已修复并验证）

> 用户实测：修复后 **能正常安装** ✅

---

## 根因 1（致命）：`resources.arsc` 被 DEFLATE 压缩

**现象**：HarmonyOS 报「无效安装包 / 与操作系统不兼容」，卸载旧版后依旧。

**原因**：

```
vanilla : resources.arsc   0.24 MB → 0.24 MB   STORED   ✅ 能装
modded  : resources.arsc   0.24 MB → 0.06 MB   DEFLATE  ❌ 装不上
```

**Android 硬性规定**：`targetSdkVersion >= 30` 的 APK，`resources.arsc` **必须 STORED（不压缩）**，
因为系统要 mmap 直接读它。压缩了这个文件，安装器直接判「无效安装包」。

**出处**：
- https://github.com/silbinarywolf/zig-android-sdk/issues/23
  > Targeting R+ (version 30 and above) requires the `resources.arsc` of installed APKs to be stored uncompressed
- https://developercommunity.visualstudio.com/t/11122235
  > MAUI Android APK ... stores resources.arsc compressed and cannot be installed on Android 11+
- https://consumer-tkb.huawei.com/weknow/servlet/show/webKnowContextServlet?knowId=en-gb15854164#1
  （华为官方「Invalid APK」的三个原因，第 1、2 条对应用户截图）

**代码位置**：`rebuild2_fast.py` 第 41-48 行

```python
# 错误写法
low = info.filename.lower()
if low.endswith(NO_DEFLATE):   # resources.arsc 不在这列表里
    STORED
else:
    DEFLATE                    # ← 被压了

# 修复后
if info.filename == "resources.arsc":
    zi.compress_type = zipfile.ZIP_STORED
    ...
    continue
```

**守门**：`validate.py` 新增第 22 项检查，重建时会直接报出来。

## 根因 2（次致命）：签名算法用了 SHA384withRSA

```
旧 modded : SHA384withRSA   ← HarmonyOS 拒装
vanilla   : SHA256withRSA   ← Lyra 官方用的
```

**修复**：重新生成 keystore，`-sigalg SHA256withRSA`，`build.py` 的 `KEYSTORE` 切到 `dol_sha256.jks`。

## 我自己犯的两个判断错误（记下来）

### 1. 说「没有 v2/v3 签名字块」

**错**。我搜的是文件尾部 64KB，但 **APK Signing Block 在 Central Directory 之前**，根本不在尾部。

正确检测：读 EOCD 拿 CD offset → 在 CD 起点前搜 `APK Sig Block 42`。

### 2. 一开始只对比「有没有签名」，没对比「用什么算法签的」

`keytool -printcert -jarfile xxx.apk | grep 签名算法` 一条命令就能查出来，我却绕了一大圈。
