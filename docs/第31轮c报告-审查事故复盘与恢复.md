## 一、事故经过

按用户要求跑 10 轮审查，第 7 轮（繁简与英文残留）时发现 `MapleBirchCE` 里有 170 条英文特质描述（作弊面板的"特质图鉴"）。

**我做了三件错事**：

### 错误 1：用正则截断 JSON，破坏了结构

```python
end = body.find('"}', idx)     # ← 找第一个 "}，遇到 text 里的引号就断
seg = body[idx:end + 2]
```

**后果**：替换后条目数从 52 变成 65，**结构损坏**。

**教训**：**绝不能用 `find('"}')` 定位 JSON 字符串边界**，必须用 `json.loads` 解析。

### 错误 2：误判"损坏"，回滚后以为没事

回滚用的是磁盘原始 `MapleBirchCE-2.1.12.mod.zip`，但**没有校验回滚后的 index 是否与上一个可用版本一致**。

**后果**：`maplebirchce.js` 的 ZIP 内容与可用版本**不一致**（差 519 字节），导致 **ModLoader 加载失败**，报 `Cannot read properties of undefined (reading 'has')`，页面 1202 秒超时。

### 错误 3：误删 `JeremieModLoader` 块

排查时发现数组里有一条 5.2MB 的"非 ZIP 条目"，**误判为垃圾数据**并删除。

**真相**：那是 **ModLoader 的索引块**（开头 `JeremieModLoader`），**必需**。

## 五、教训（写进工作守则）

### 1. 改 JSON 必须用 `json.loads`，不能用正则截断

```python
# 错
end = body.find('"}', idx)

# 对
arr = json.loads(re.sub(r",\s*\]\s*$", "]", arr_text))
```

### 2. 任何"回滚"之后必须做**全量一致性校验**

回滚 ≠ 恢复。要对比：
- 模组数量
- 每个模组 ZIP 的 MD5
- 与上一个可用版本的 index 哈希

### 3. 数组里的非 ZIP 条目不一定是垃圾

`JeremieModLoader` 块是 ModLoader 的索引，**5.2MB 且不是 ZIP**，但**必需**。
**删任何东西之前先看它在备份里是否存在**。

### 4. 有 archive 快照就有救

这次能快速恢复，靠的是 `archive\DoL-Lyra-0.5.12.13-CHS-modded_20261128_第31轮b_联动自查修正.apk`。
**每轮部署都存 archive，是硬性纪律**。
