## 二、发现并修复的问题

### 2.1 【严重·已修】孤儿院浴室解手入口重复

用户截图显示 `Bathroom` 有**两组**「小便/大便」（3/4 与 6/7）。

**根因**：BasicNeeds 的 `injectRelief()` 会往 `RELIEF_SCENES`（含 `Bathroom`）**自动注入**一组；我此前又手工加了静态入口 → 重复。

**修法**：
- 删除 `Bathroom` 的静态入口，交回 BasicNeeds 自动注入。
- 给 `injectRelief()` 的注入模板补上 `window.mee.excrete()`（露出联动），把联动从静态入口迁移到自动注入。

**验证**：`COUNT_TOILET.py` 从 7 处降到 6 处静态入口（`Bathroom` 由运行时注入）；手动调用 `injectRelief()` 后 `#bn-relief` = 1、小便 = 1。

### 2.2 【回归·已修】猫咖 `Containers` 补丁锚点

**现象**：`G2 模组补丁零错误` 报猫咖 `findString` 失配。

**根因**：`Containers` 在**静态 index** 里没有 `<<handheldon>>`，但**运行时**被 DoLSims 的补丁加上了 —— 两种 `findString` 写法必有一种失配（带/不带都试过）。

**修法**：移除猫咖的这条 `Containers` 补丁（只影响「离开书房」一个链接，价值低于 G2 清零）。

**验证**：G2 = 0 条。

### 2.3 【遗漏·已修】`lock.png` 资源注入未纳入打包流程

**现象**：重新打包后 G9 又报 `img/ui/phone/lock.png` 404。

**根因**：`lock.png` 是**直接注入 APK 的 `assets/www/`** 的，不在 index 里；`CUR19_pack.py` 每次重新打包都会丢掉它。

**修法**：抽出独立步骤 `INJECT_LOCK.py`（可复用），在签名前执行。

**验证**：G9 404 = 0。

### 2.4 【记录·未修】Remy Love 把战斗文本覆盖成英文

**现象**：`Remy.Love.Mod` 的 `game/base-combat/actions-text.twee` 覆盖了原版 `Widgets Actions Text`。

| | 中文汉字 | 英文单词 |
|---|---|---|
| 原版 `Widgets Actions Text` | 25,889 | 8,806 |
| Remy Love 覆盖版 | **756** | **20,229** |

**结论**：模组本身没有 `Languages` 目录、没有翻译字段，作者用英文重写了整个 widget。玩家在战斗中会看到**大量英文动作描述**。

**未修原因**：3,368 行英文，且本机**没有可用的翻译 API**（无 `.env`、无 `DEEPSEEK_API_KEY`、历史翻译脚本全是人工 MAP）。人工逐行翻译不现实。

**建议**：要么接受英文，要么移除 Remy Love，要么后续接入翻译 API 再处理。
