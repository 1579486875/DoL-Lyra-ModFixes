## 本轮修的内容

### 1. 模板字符串里"变量名+中文"粘连（3 处，真 bug）

反引号模板里，属性名后面直接跟中文，JS 会把它们当成一个整体标识符。

| 错 | 对 |
|---|---|
| `用$valueGucket.nameText浇灭 (0:01)` | `用${ $valueGucket.nameText }浇灭 (0:01)` |
| `在$valueGucket.nameText中清洗 (0:05)` | `在${ $valueGucket.nameText }中清洗 (0:05)` |
| 用_stick.state火把和它玩拔河游戏 | 用${ _stick.state }火把和它玩拔河游戏 |

### 2. 中文文本里的英文残留（4 处）

| 错 | 对 |
|---|---|
| 按enter键继续 | 按回车键继续 |
| 给了你一个Wink | 朝你抛了个媚眼 |
| 你喜欢束缚play？ | 你喜欢束缚玩法？ |
| 心中想着the Black Wolf。 | 心中想着（NPC 中文名） |

## 重要认知：`state火把` 类不是 bug

SugarCube 的 `$var` / `_var` 语法**只匹配 [A-Za-z0-9_.]**，
所以 `$itemActionObject.state火把不被接受` 里，变量是 `$itemActionObject.state`，后面"火把"是正常中文文本。

**只有反引号模板里才需要 ${...}。**

这个认知避免了大量误报（第一版扫出 2267 处"变量名含中文"，全是误报）。
