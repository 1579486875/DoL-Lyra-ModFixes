## 6. 本轮发现的模板/脚本问题（判据失效）

| # | 问题 | 教训 |
|---|---|---|
| 1 | `Get-Content` 按 ANSI 读 UTF-8 → 乱码 | 模板 §3.4 已警告，本次踩到 |
| 2 | `"<<" + "</if>"` = `'<<</if>'`（三个 `<`） | **拼接闭合宏要写 `"<" + "</if>" + ">"`** |
| 3 | `<<set $x to Ellipsis>>` 多行宏剥离不干净 → HTML 检查假阳性 | **SugarCube 的宏语法让 HTML 标签检查不可靠，改用 CDP** |
| 4 | `<<script>>` 在 JSDoc 注释里被当成真宏 → 吞掉 3.5 MB | **要判断 body 首行是否像散文** |
| 5 | 变量名正则用 `\w` 吞中文 → `$_ly和` | **变量名用 `[A-Za-z_][A-Za-z0-9_]*`** |
| 6 | `build_all` 正则用 `\\`（双反斜杠）→ 匹配不到 | **raw string 里 `\` 就是 2 个字符** |

**六次全是审计脚本自身的口径错 —— 印证模板 §6.2「先怀疑脚本，再怀疑数据」。**
