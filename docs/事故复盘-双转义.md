# 事故复盘：index 双重转义（`html.escape` 整文件）

> 发生时间：2026-11-20 07:12
> 影响：一个包（`6014337C`）完全无法启动，已回滚

---

## 现象

```
index 长度: 97,513,548
tw-passagedata 数: 0          ← 应该 16,089
开头: '&lt;!DOCTYPE html&gt;&lt;html data-init="no-js"&gt;'
```

整个 `index.html` 被 HTML 转义了一次，`<tw-passagedata>` 全变成 `&lt;tw-passagedata&gt;`，
SugarCube 解析不到任何 passage，游戏白屏。

## 根因

`Z03_fix_mod_text.py` 里：

```python
g = html.unescape(data)          # 解码 → 全明文
new_g = g[:a] + new_block + g[b:]  # 改 base64 段
data = html.escape(new_g, quote=False)   # ← 又全部转义！
open(HTML, "wb").write(data.encode("utf-8"))
```

**`DoL` 的 `index.html` 是「全明文」形态**（不是半转义），
`unescape` + `escape` 一来一回就变成了「全转义」。

## 事故链

1. `Z03` 写入全转义 index
2. `ZZ02`（也用了 `escape`）继续转义
3. `build.py` 打包，`rebuild2_fast.py` 只替换 `index.html` 内容
4. 签名、归档、`validate.py` **22/22 通过**（因为它只查文件体积/宏配对，不查 passage 数）
5. 用户装上 -> 白屏

**`validate.py` 没能拦住**，这是最大的教训。

## 修复

### 1. `Z03` / `ZZ02` 重写：不再 `escape` 整文件

```python
# 正确做法：直接在明文 data 上做字符串替换
data = open(HTML, "rb").read().decode("utf-8", "replace")
data = data.replace(old, new)
open(HTML, "wb").write(data.encode("utf-8"))
```

### 2. 两个脚本都加安全阀

```python
if len(re.findall(r"<tw-passagedata", data)) < 10000:
    print("❌ index 不是明文形态，拒绝修改")
    sys.exit(1)
```

### 3. `rebuild2_fast.py` 加打包前门禁

```python
_html_probe = open(NEWHTML, "rb").read().decode("utf-8", "replace")
_n_raw = len(re.findall(r"<tw-passagedata", _html_probe))
_n_esc = len(re.findall(r"&lt;tw-passagedata", _html_probe))
if _n_raw < 10000:
    print("❌ index 不是明文形态，拒绝打包")
    sys.exit(1)
```

### 4. 回滚

把 `0A316E37`（用户验证能装）的 `index.html` 覆盖回 `index_modded6.html`，
再重跑 `ZZ02` + `Z03`。

## 教训

**修改 `index.html` 的脚本，绝不允许对整文件做 `escape` / `unescape`。**

`DoL` 的 `index.html` 是全明文，任何「先 unescape 再 escape」都会双重转义。
正确做法是**直接在原始字符串上做精确替换**，改不到的地方说明锚点写错了，应该修锚点而不是转义整个文件。

**另外**：`validate.py` 的 22 项检查里**没有 passage 数检查**，
所以全转义的包也能通过 —— 已加入 `rebuild2_fast.py` 的打包门禁。
