## 二、关键发现：`name` 不能翻译

### 2.1 踩的坑

第一次我把 `name` 也翻译成中文，结果**页面加载失败**（1200 秒超时，报 `Cannot read properties of undefined (reading 'has')`）。

### 2.2 根因

`MapleBirchCE` 里有一个 **`TRAIT_ZH`** 映射表：

```js
var TRAIT_ZH = {
    "Virgin": "童贞", "Chastity Vow": "贞洁誓言", "Broken Vow": "破誓",
    "Rite of Promise": "承诺仪式", ...
};
```

**它用英文 `name` 做 key**。

代码里：

```js
var nameZh = TRAIT_ZH[t.name] || TRAIT_ZH_SERIES... ;
```

我把 `t.name` 改成中文后，`TRAIT_ZH["处子之身"]` → **undefined** → 下游崩溃。

### 2.3 正确做法

| 字段 | 处理 | 原因 |
|---|---|---|
| **`name`** | **保持英文** | 靠 `TRAIT_ZH` 映射显示中文，改了就断链 |
| **`text`** | **翻译成中文** | 没有映射表，直接用 |

### 2.4 最终效果

- **界面显示**：`TRAIT_ZH["Virgin"]` → **童贞**（模组自带映射）
- **描述显示**：`text` 里的中文 → **你的纯洁恢复得更快…**

## 四、教训（补充进工作守则）

### 5. 改任何数据表之前，先搜有没有配套的映射表

这次 `TRAIT_ZH` 就是反例：
- 表面上 `VANILLA_TRAITS_RAW` 是英文
- 实际上**界面显示走的是 `TRAIT_ZH[name]` 映射**
- **改 `name` = 拆掉映射的 key**

**正确做法**：搜 `表名` 的所有引用，看有没有 `XX_ZH`、`XX_CN`、`XX_MAP` 之类的配套映射。

### 6. 函数式字段要改内部字符串，不要整体替换

`text` 是 `() => {...}` 时：
- ❌ 把整个函数换掉（会破坏逻辑）
- ✅ 只替换函数体里的**字符串字面量**

这次用的就是"片段替换"（`FRAGMENT_TRANS`），验证有效。

### 7. 发现上游数据截断时，先确认是不是自己造成的

`生发配方` / `抗寄生虫乳膏` 的截断，我先怀疑是自己，直到对比磁盘原始模组才确认是**上游 bug**。
