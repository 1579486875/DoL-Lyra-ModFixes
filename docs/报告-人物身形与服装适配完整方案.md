# 人物身形与服装贴图适配问题 · 完整解决方案报告

**日期**：2026-11-27
**对象**：`DoL-Lyra-0.5.12.13-CHS-modded.apk`（我们的包）
**结论先行**：**问题确认存在，根因是"美化包重绘了身体但服装没跟上"，不是我们的汉化/修复造成的。有三条可行路线，我建议先做程序化变形的 PoC。**

---

## 摘要

你观察到的现象（衣服飘离、穿过人物、覆盖不全、胸部变体缺失）**全部属实**，而且**你关于"服装是按旧身形画的"的判断完全正确**。

经过逐图哈希对比，我们的包与 Lyra「基础版」有 **9,801 张图不同**，其中**身形核心图层（base-classic/curvy/slender/soft、breasts-0~6）全部被替换**：

| 文件 | 基础版 | 我们的包 | 差异 |
|---|---|---|---|
| `base-curvy.png` | 256×128，**634 字节** | 512×256，**12,688 字节** | **20 倍** |
| `breasts-6.png` | 256×128，**308 字节** | 512×256，**17,657 字节** | **57 倍** |

**我们的包是 BEEESSS 系的 512×256 高清重绘身形，而大量服装贴图仍是原版比例/原版轮廓。**

## 二、根因分析（三层叠加）

### 第一层：美化层（BEEESSS）

BEEESSS 把身体**重绘成 512×256 高清版**：

- 身体轮廓变宽、变圆
- 胸部更柔和、更有体积感
- 皮肤有渐变和阴影

**但服装贴图没有同步重绘。**

### 第二层：社区适配层（半成品）

社区确实做了补图仓库：

> [BEEESSS Community Sprite Compilation](https://gitgud.io/ChiaraSiegel/kaervek-beeesss-community-sprite-compilation)
> *"This is my compilation pack of sprites made by the community to complement the BEEESSS mod for DOL."*

**但作者本人承认适配质量有限**：

> [Degrees of Lewdity Graphics Mod](https://gitgud.io/mommehy/degrees-of-lewdity-graphics-mod) 的 README：
> ***"Many of the clothes and body writing are just hap-hazardly nudged into place for now."***
> （**很多衣服和身体纹身目前只是随手挪了一下位置**）

**这句话是整件事的关键**：不是"没做适配"，而是**"做了但只是挪位置，不是按新身形重绘"**。

### 第三层：原版资源层（先天不足）

原版 DoL 自己就有这个问题，作者在 GitLab 上说过：

> *"Now clothes use the same size as breasts, but capped at 5, because **most clothes don't have 6.png files**."*

**三层叠加的结果**：

```
美化重绘身体（512×256，轮廓变宽）
        ↓
服装贴图没重绘（还是原版 256×128 轮廓）
        ↓
社区只"挪位置"（不是按新轮廓重画）
        ↓
原版本身还缺 74% 平胸版、49% 最大胸版
        ↓
= 衣服飘离、穿模、覆盖不全、变体缺失
```

### 2.4 「束腰挡右胸」的具体成因

`corset` 的配置：

```javascript
index: 15,              // 图层顺序：在胸部之上
bustresize: 2,          // 穿上后胸部视觉缩小 2 级
combat: { hasBreasts: true }
```

**三重问题**：

1. **`index: 15`** —— 束腰图层在胸部之上
2. **贴图没挖空胸部区域** —— `corset/4.png` 只有中间一小块，但**覆盖图层（right-cover）**会盖住
3. **尺寸不匹配** —— 玩家胸大时，胸部溢出到束腰贴图之外，但覆盖层还是盖上去

**这就是"右胸被挡住"的机制**。

### 3.4 中文社区的教程

百度贴吧有一份改图教程，讲了 DoL 贴图的结构：

> 1. 基础原理：DoL 分为主程序 `Degrees of Lewdity.html` 和贴图文件 `img` 两部分，通过主程序对应项中的数据指定对应贴图。因此**自制美化 mod 也分为两种——衣物添加（修改 html 和 img）与衣物替换（只改 img）**
> 3. 图层原理：游戏中，各个贴图图层按照一定顺序排列，以防止添加或移除场景/动作/衣物出现错位
> 5. 贴图尺寸：游戏贴图规格一般有 **512×256（可动图层）**、**256×256（不动图层）**、**30×30（缩略图）** 三种

**这给出了制作方案的技术基础**。

### 3.5 有人遇到过完全相同的问题

## 四、AI 方案（详细）

### 4.1 三条技术路线对比

| 路线 | 原理 | 优点 | 缺点 | 适合 |
|---|---|---|---|---|
| **A. 程序化变形** | 按轮廓差异做弹性 warp | 100% 保风格、可批量、自动 | 大幅变形会糊 | **尺寸差异类问题**（我们这种） |
| **B. AI Inpainting** | mask 圈区域，SD 重绘 | 能补完全缺失的变体 | 像素风一致性差、要手修 | **补 6.png 这类全缺的** |
| **C. 手动重绘** | Aseprite / PS | 质量最高 | 每件 30–60 分钟 | 关键服装 |

### 4.2 路线 A：程序化变形（推荐先试）

**原理**：

```
取 corset/4.png（已有）
取 breasts-4.png 和 breasts-5.png 的 alpha 轮廓
计算两个轮廓之间的"位移场"（displacement field）
用这个位移场 warp corset/4.png
输出 corset/5.png
```

**技术实现**：

```python
# 伪代码
import numpy as np
from PIL import Image
from scipy.ndimage import map_coordinates

# 1. 提取两个胸部图的 alpha 轮廓
alpha4 = np.array(Image.open("breasts-4.png").split()[-1])
alpha5 = np.array(Image.open("breasts-5.png").split()[-1])

# 2. 用光流/最近邻匹配算位移场
flow = estimate_flow(alpha4, alpha5)   # (H, W, 2)

# 3. 对服装图做 warp
cloth = np.array(Image.open("corset_4.png"))
warped = warp_image(cloth, flow, order=1)   # 双线性插值

# 4. 保存
Image.fromarray(warped).save("corset_5.png")
```

**优点**：
- **不需要 AI**，纯确定性算法
- **风格 100% 保持**（只是搬像素）
- 可以**批量跑**（265 个服装 × 缺失尺寸）

**难点**：
- 位移场估计质量决定成败
- 大幅变形（如 4→6）会糊

**改进**：
- 用**分区域变形**（胸部区域强变形，其他区域不动）
- 用 **`scipy.ndimage.map_coordinates`** 做亚像素插值

### 4.3 路线 B：AI Inpainting（补完全缺失的变体）

**适用场景**：`6.png` 完全不存在，或变形效果太差。

**工具链**（全网搜到的）：

| 工具 | 特点 | 链接 |
|---|---|---|
| **Retro Diffusion** | 真像素网格、**透明背景**、内置 inpaint/outpaint/调色板转换 | [retrodiffusion.ai](https://seektool.ai/ai/retrodiffusion-ai) |
| **Pixel Fashion Atelier** | 基于 SD + Anything-v5，**专做像素时装贴图** | [CSDN 教程](https://blog.csdn.net/weixin_42587866/article/details/159482112) |
| **spriteloom-mcp** | **MCP 服务器**，`inpaint_sprite`（带 mask 局部重绘，保留 mask 外像素） | [glama.ai](https://glama.ai/mcp/servers/AlexPascu007/spriteloom-mcp/tools/inpaint_sprite) |
| **ComfyUI Text2PixelCharacter** | 512×512 像素角色，**跨生成保持调色板一致** | [comfy.icu](https://comfy.icu/node/Text2PixelCharacter) |
| **MagicPixel** | 真像素网格，16×16 到 1024×1024 | [submitaitools.org](https://submitaitools.org/magicpixel-art/) |
| **PixelLab & Sprite Tools** | 透明背景精灵生成 + 编辑工作流 | [sorceress.games](https://sorceress.games/wiki/wizard-genie/pixellab-and-sprites) |

**具体流程**：

```
1. 拿 corset/5.png（已有）做底
2. 用 mask 圈出"需要扩展到 6 号胸"的区域
3. 输入 SD + ControlNet（Canny/Lineart 锁定线稿）
4. 提示词：
   positive: "pixel art clothing sprite, corset, transparent background,
              clean lineart, flat colors, 512x256, game asset"
   negative: "photorealistic, 3d render, blurry, gradient, shadow, background"
5. 生成 4-8 张候选
6. 选中最好的一张，用 PIL 对齐到 512×256
7. 手动修边缘（去毛边、补错位像素）
```

**关键提示词技巧**（从 [Geniea 的 SD 像素时装提示词](https://www.geniea.com/prompts/sd-pixel-art-fashion) 总结）：

- **必须锁定**：`pixel art`、`flat colors`、`limited palette`、`transparent background`
- **必须排除**：`gradient`、`shadow`、`blur`、`3d`、`photorealistic`
- **尺寸**：必须显式写 `512x256` 或生成后裁切

**缺点**：
- **像素风一致性差**——SD 很难 100% 复刻原来的像素密度
- **透明背景容易出错**——需要后处理
- **每件都要手修**

### 4.4 路线 C：混合（我的推荐）

```
第 1 步：用路线 A（程序化变形）批量生成所有缺失变体
第 2 步：用脚本检测"变形质量差"的（如拉伸过度、透明区域破损）
第 3 步：对质量差的用路线 B（AI）重做
第 4 步：对关键服装（束腰、胸罩、常见上衣）人工精修
```

## 五、可执行计划（分阶段）

### 阶段 0：验证（1–2 小时）

1. **下载 AU-F 版 Lyra 包**，对比它的服装贴图是否**配套重绘**
   - 如果是 → **直接换 AU 版更省事**
   - 如果不是 → 进入阶段 1

### 阶段 1：PoC（我能做，2–4 小时）

**目标**：拿 `corset` 试，产出 `0.png` 和 `5.png`

1. 写脚本：从 `breasts-N.png` 提取轮廓差异 → 计算位移场
2. 对 `corset/1.png`（最接近 0）和 `corset/4.png`（最接近 5）做 warp
3. 输出到包里，打包
4. **你装上直接看效果**

**判断标准**：
- 服装能贴合胸部轮廓
- 没有明显糊化
- 透明背景完整

### 阶段 2：批量（如果 PoC 通过）

1. 扫描所有 `265` 个有变体的服装，找出**缺失的尺寸**
2. 对每个缺失尺寸，用相邻尺寸做 warp
3. 批量输出，打包，验证

**预估**：脚本跑 1–2 小时，人工抽查 1 小时。

### 阶段 3：精修（按需）

对关键服装（束腰、胸罩、泳装、常见上衣）用 Aseprite 手动修。

### 阶段 4：图层问题单独处理

「束腰挡右胸」可以用官方 MR [!3041] 的思路：

> *"Turned the corset sprites into **underbust** sprites instead of odd floating coloured boobs"*

**做法**：
1. 把束腰贴图的**胸部区域挖空**（改成只覆盖下乳）
2. 或把 `index: 15` 调低（但会穿模）

**推荐**：改贴图（挖空），而不是改 index。

## 六、风险评估

| 风险 | 影响 | 缓解 |
|---|---|---|
| 程序化变形糊化 | 视觉质量下降 | 只对小幅差异（±1 级）用 warp，大幅用 AI |
| AI 生成风格不一致 | 服装看起来"不像同一套" | 用 ControlNet 锁线稿 + 限定调色板 |
| 改贴图破坏原有服装 | 某些服装变丑 | **先备份，PoC 验证后再批量** |
| 打包体积增大 | APK 变大 | 可接受（当前 180 MB） |
| 与上游更新冲突 | 上游更新后要重做 | 脚本化，可重跑 |
