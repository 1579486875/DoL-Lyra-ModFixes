## 2. 事故：index 双重转义（已修复）

### 现象

```
index 长度: 97,513,548
tw-passagedata 数: 0          ← 应该 16,089
开头: '&lt;!DOCTYPE html&gt;&lt;html …'
```

**整个 index 被 HTML 转义一次**，SugarCube 解析不到任何 passage，游戏白屏。

### 根因

`Z03_fix_mod_text.py`：

```python
g = html.unescape(data)                  # 解码 → 全明文
new_g = g[:a] + new_block + g[b:]
data = html.escape(new_g, quote=False)   # ← 又全部转义！
```

**`DoL` 的 `index.html` 是「全明文」形态**，`unescape` + `escape` 一来一回就变成全转义。

### 为什么 `validate.py` 没拦住

22 项检查里**没有 passage 数检查**，一个 0 passage 的包也能 22/22 通过。

### 修复

1. **`Z03` / `ZZ02` 重写**：不再 `escape` 整文件，直接在明文 data 上做精确替换
2. **两个脚本加安全阀**：
   ```python
   if len(re.findall(r"<tw-passagedata", data)) < 10000:
       print("❌ index 不是明文形态，拒绝修改"); sys.exit(1)
   ```
3. **`rebuild2_fast.py` 加打包前门禁**：passage < 10000 直接拒绝打包
4. **回滚**：用 `0A316E37`（用户验证能装）的 index 作基线，重跑 `ZZ02` + `Z03`
