## 一、做了什么

新建了一个独立模组 **`系统联动补全`**，把原本互不相干的系统接起来。

**设计铁律**（全程遵守）：

| 原则 | 落实 |
|---|---|
| **只读现状，只加副作用** | 只用 `$stress` / `$trauma` / `$fame` / `$arousal`，**不碰** `$exposed`、战斗公式、渲染层 |
| **不反常识** | 所有阈值和系数都基于实测参数（见下表） |
| **可单独禁用** | 5 个联动各有开关，存在 `V.联动.on.*` |
| **删模组即回退** | 不改任何现有文件 |
| **出错不崩** | 所有读写包在 `safe()` / `try-catch` 里，异常静默跳过 |

## 二、5 组联动

### 联动 1：失禁 → 羞耻 / 名声

**触发**：`$BasicNeeds.bladder` 从 ≥9000 跳到 0，且不在解手场景

| 场合 | 效果 |
|---|---|
| 在自家 | `stress +150` |
| 无人 | `stress +300` |
| 公共 + 不在意裸体 | `stress +700`，`fame +2`，`arousal +40` |
| 公共 + 在意裸体 | `stress +1800`，`trauma +120`，`fame +5` |

**文本**：4 套独立文案（在家 / 私密 / 公共不在意 / 公共羞耻）

**验证**：4 种场合 + 冷却 + 开关，全部通过

---

### 联动 2：服装破损 → 走光

**触发**：`$worn.<槽位>.integrity / integrity_max`

| 破损比例 | 效果 |
|---|---|
| ≥ 0.7 | 无 |
| 0.35 – 0.7 | `stress +20`，文本「衣服磨得薄了」 |
| < 0.35 | `stress +60`，`fame +1`，文本「裂开了一道口子」 |

**只算**：`upper` / `lower` / `under_upper` / `under_lower`（裸体跳过）
**冷却**：同槽位 5 分钟

**验证**：完好 / 半透 / 走光 / 全裸 / 冷却，全部通过

---

### 联动 3：需求 → 战斗表现

**触发**：`$combat` 从 false → true（**只在开战瞬间结算一次**，不逐回合刷）

| 需求 | 效果 |
|---|---|
| 尿意 ≥ 8000 | `stress +300`，文本「小腹涨得发疼」 |
| 口渴 ≥ 8000 | `stress +200`，文本「喉咙干得发疼」 |

**不改**任何战斗数值，只加压力与提示
**冷却**：5 分钟

**验证**：尿急 / 口渴 / 正常 / 不在战斗，全部通过

### 联动 4：拍照 → 暴露名声

**触发**：`$Phone.photography` 增长（每次拍照 +1，上限 1000）

| 场合 | 效果 |
|---|---|

**验证**：公共 / 暴露 / 没拍 / 私密，全部通过

---

### 联动 5：在自家 → 放松（反向反馈）

**触发**：在自家房产 + `$exposed ≥ 1`

**效果**：`stress -= min(200, max(20, stress × 8%))`，文本「反正是自己家」

**设计意图**：原版在自家裸体一样会算暴露名声，这里给一个**正向的安全区反馈**——不改原版名声，只削减压力。

**冷却**：3 分钟

**验证**：在家放松 / 没暴露 / 在外面 / 压力为零，全部通过

## 三、参数依据（全部实测，非估算）

| 参数 | 实测值 | 来源 |
|---|---|---|
| `$stressmax` | **10000** | `Widgets variablesStart2` |
| `$traumamax` | **5000** | 同上 |
| `$arousalmax` | **10000** | 运行时读取 |
| `$fame.exhibitionism` 上限 | **2000** | 原版 `Math.clamp(..., 0, 2000)` |
| `BasicNeeds.MAX` | **10000** | `Ban-core.js` |
| `RATES.thirst` | **2000/h** | `Ban-core.js` |
| `RATES.bladder` | **1333/h** | 同上 |
| 失禁条件 | `bladderFullHrs >= 1` | `Ban-needs.js` |
| 拍照上限 | **1000**（每日 10 次） | `smartphone-vars.js` |

**数值平衡**：
- 单次最大 `stress +1800`，相对 10000 上限 = 18%
- 单次最大 `fame +5`，相对 2000 上限 = 0.25%
- 所有联动都有冷却，不会刷

## 四、实现过程中修掉的问题

| 问题 | 根因 | 修法 |
|---|---|---|
| 模组不加载 | JS/twee 文件名用中文，ModLoader 按路径读不到 | 改 `core.js` / `text.twee`（符合命名约定例外条款） |
| 数值全为 0 | 测试缓存了 `State.variables`，`Engine.play` 后引用失效 | 测试每次重新取 `V = S.State.variables` |
| 文本不插入 | 选择器 `#passages .passage:last .passage-content` 不匹配 | 改多重兜底选择器 |
| 检测不到失禁 | `BasicNeeds` 也挂 `:passageend`，先跑会把 bladder 重算 | `:passageend` 里用 `setTimeout(0)` 延后一帧 |
| `inPublic()` 判定错 | 只读 `State.passage`，测试时是 `Start2` | 统一 `currentPassage()`，测试用真跳转 |

## 六、模组信息

```
系统联动补全 v1.0.0
├─ boot.json
├─ scripts/core.js      （约 400 行，全部带 try-catch）
└─ twee/text.twee       （9 个文本 widget）
```

**状态字段**：

```js
V.联动 = {
    version: 1,
    debug: false,
    on: { accident: true, tear: true, battle: true, photo: true, home: true },
    cool: {},           // 各联动冷却时间戳
    lastBladder: null,
    lastBladderFull: 0,
    lastPhoto: null,
    lastCombat: false
}
```

**回退**：在 ModLoader 里禁用「系统联动补全」，或直接删除该模组，**不影响任何其他内容**。
