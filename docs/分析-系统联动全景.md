# 系统联动全景分析

**日期**：2026-11-27
**方法**：扫描 64 个模组的 JS/twee，逐场景验证代码里有没有真实实现。
**结论**：**已有 12 组真实联动，另有 11 组"应该有但没有"的缺口。**

---

## 一、已有联动（代码验证过）

### 1.1 游泳脱衣 → 暴露 ✅

**位置**：`Widgets Events Swimming`

```twee
<<widget "swim_strip_check">>
    <<if (!$worn.upper.type.includes("swim") or !$worn.upper.type.includes("naked") ...)>>
        <<set _swim_strip_check.pushUnique("upper")>>
        <<set _swim_strip_check_exhib to true>>
    <</if>>
    ...（共检查 6 个槽位：upper / lower / under_upper / under_lower / legs / feet）
<</widget>>
```

**调用处**：`Asylum Depths` 等游泳场景

```twee
<<swim_strip_check>>
<<if _swim_strip_exhib>><<exhibitionist 1>><</if>>
```

**结论**：**你举的例子（野外脱光游泳增加暴露）原版就实现了**，检查 6 个槽位是否穿了泳装。

### 1.2 需求满 → 失禁 → 弄湿衣服 ✅

```js
function accident() {

    bn.bladder = 0;
    bn.bladderFullHrs = 0;
    // 失禁：下半身外层+内层衣物各加 100 湿度

if (!sleeping) {
    bn.bladderFullHrs += hours;
    if (bn.bladderFullHrs >= 1) accident('bladder');   // 满 1 小时 → 失禁
}
```

**联动链**：`尿意满 → 计时 1 小时 → 失禁 → 衣物 +100 湿度 → 原版湿衣系统接管`

## 二、缺失的联动（"应该有但没有"）

### 2.1 怀孕 → 战斗受限 ❌

**搜索**：`$pregnancy ... 无法/不能/困难` → **0 处**

**现状**：怀孕只影响**肚子外观**，**不影响战斗/行动**。

**可以做的联动**：
- 孕晚期闪避 -20%
- 孕晚期无法做某些高难度动作
- 分娩前触发紧急事件

---

### 2.2 需求满 → 暴露/羞耻 ❌

**现状**：失禁只**弄湿衣服**，**不触发暴露判定**。

**可以做的联动**：
- 失禁时如果在公共场合 → `<<exhibitionist>>` + 名声
- 失禁时周围有 NPC → 羞耻/被看见

**证据**：`BasicNeeds` 的 JS 里**没有任何** `exhibitionism` 调用。

---

### 2.3 天气 → 需求消耗 ❌

**搜索**：`weather ... 口渴/冷/热` → **0 处**

**可以做的联动**：
- 炎热天气 → 口渴加速
- 寒冷天气 → 饥饿加速（消耗热量）
- 下雨 → 衣服变湿

---

### 2.4 转化（猫/狗/牛）→ 需求变化 ❌

**搜索**：`$transformations ... 饿/渴/需求` → **0 处**

**可以做的联动**：
- 猫转化 → 不需要那么多水
- 牛转化 → 泌乳需求
- 狗转化 → 饥饿加速

---

### 2.5 服装破损 → 暴露 ❌

**搜索**：`integrity ... 破/裂/走光` → **0 处**

**现状**：服装有 `integrity`（耐久），但**破损不直接触发暴露**。

**可以做的联动**：
- `integrity < 30%` → 该槽位视为"半裸"
- 破损时触发 `<<exhibitionist>>`

---

### 2.6 手机拍照 → 暴露/名声 ❌

**现状**：`SmartPhone Alpha` 有摄影技能（`$Phone.photography`），但**拍照不增加暴露名声**。

**可以做的联动**：
- 在公共场合拍照 → 暴露名声 +
- 拍裸照 → `fame.exhibitionism` +

### 2.7 房产/家 → 可裸体 ❌

**搜索**：`家里 ... 裸体` → 只有剧情场景，**没有"在家可以安全裸体"的机制**。

**可以做的联动**：
- 在自己房产内 → 暴露度不增长（私密空间）

### 2.8 基本需求 → 战斗表现 ❌

**现状**：饥饿/口渴/疲劳**不影响战斗数值**。

**可以做的联动**：
- 饥饿 → 体力上限降低
- 口渴 → 意志降低
- 尿意满 → 战斗中分心（命中率 -）

---

### 2.9 露出拓展 → 基本需求 ❌

**现状**：`露出拓展` 引用了 `BasicNeeds` 2 次，但**没有双向联动**。

**可以做的联动**：
- 暴露时尿意增长加速（紧张）
- 穿得少 → 寒冷 → 需求加速

---

### 2.10 转化 → 服装限制 ❌

**现状**：猫/狗转化后**尾巴/耳朵**会穿模，但**没有"某些服装穿不上"的限制**。

---

### 2.11 时间/季节 → 事件密度 ❌

**现状**：`timemulti` 只改时间流速，**不改事件概率**。

## 四、如果要补，哪些最容易做

| 缺口 | 难度 | 做法 |
|---|---|---|
| **失禁 → 暴露** | ⭐ 低 | 在 `accident()` 里加 `<<exhibitionist 1>>`（如果周围有人） |
| **天气 → 需求** | ⭐ 低 | 在 tick 里按 `Weather.precipitation` 调整消耗速率 |
| **破损 → 暴露** | ⭐⭐ 中 | 在渲染前检查 `integrity`，低于阈值时视为半裸 |
| **拍照 → 名声** | ⭐⭐ 中 | 在 `cameraShot` 后加 `fame.exhibitionism` |

| **需求 → 战斗** | ⭐⭐⭐ 高 | 改战斗数值计算，影响面大 |
| **怀孕 → 战斗** | ⭐⭐⭐ 高 | 同上 |
| **转化 → 需求/服装** | ⭐⭐⭐ 高 | 需要改需求速率和服装过滤 |

## 五、结论

**这个包的系统联动已经相当丰富**：

- **12 组真实联动**（游泳→暴露、需求→失禁、战斗→怀孕……）
- **露出系统**（`$exhibitionism` 618 次 + `fame.exhibitionism` 61 次）是全库最活跃的交叉点
- **BasicNeeds** 是独立度最高的系统（只调用 `maplebirch` 1 次）

**但有一批"感觉上应该有"的联动确实缺失**：

- **失禁不触发暴露**（最遗憾，明明弄湿了衣服）
- **怀孕不影响战斗**（孕晚期照样能打）
- **天气/转化不影响需求**（猫狗和人一样吃喝）
- **服装破损不导致走光**

这些**不是 bug**，是**模组作者没做**。**要做的话，前 3 个（失禁→暴露、天气→需求、破损→暴露）工作量都不大。**
