# 安装失败根因：签名算法 SHA384withRSA（HarmonyOS 不认）

## 现象

手机报「无效安装包 / 与操作系统不兼容」，卸载旧版后仍然如此。

## 排查过程

| 检查项 | 结果 |
|---|---|
| ZIP 完整性 | ✅ 33,491 条目，testzip OK |
| v1 签名 | ✅ SHA-256-Digest × 33,488 |
| v2/v3 签名字块 | ✅ signature verified [v1, v2, v3]（注意：在 Central Directory **之前**，不在文件尾） |
| zipalign | ✅ verified |
| minSdkVersion | 22（手机 API 26，够） |
| targetSdkVersion | 32 |
| META-INF 结构 | ✅ 与 vanilla 完全一致 |
| 首次条目 | AndroidManifest.xml ✅ |
| ZIP64 / 重复条目 / 异常文件名 | 都没有 ✅ |

## 真凶

`
modded  : SHA384withRSA   ← HarmonyOS 拒装
vanilla : SHA256withRSA   ← Lyra 官方用的
`

**keystore 的 -sigalg 用了 SHA384withRSA，而 HarmonyOS 只认 SHA256withRSA。**

## 修复

`powershell
keytool -genkeypair -keyalg RSA -keysize 2048 -sigalg SHA256withRSA -validity 10000 
  -alias dol -keystore dol_sha256.jks -storepass dolchs -keypass dolchs 
  -dname "CN=DoL Lyra, OU=Mods, O=DoL, L=NA, ST=NA, C=CN"

java -jar uber-apk-signer.jar -a build_next_unsigned.apk --out signed_sha256 
  -ks dol_sha256.jks --ksAlias dol --ksKeyPass dolchs --ksPass dolchs
`

uild.py 的 KEYSTORE 已从 dol.jks 切到 dol_sha256.jks。

## 教训

**签名算法要和目标平台一致。** 之前只看「有没有签名」，没看「用什么算法签的」。
用 keytool -printcert -jarfile xxx.apk | grep 签名算法 一条命令就能查出来。

## 顺带纠正

之前我判断「没有 v2/v3 签名字块」是**错的** —— 我搜的是文件尾部 64KB，
而 APK Signing Block 在 **Central Directory 之前**。正确检测法：
读 EOCD 拿 CD offset → 在 CD 起点前搜 APK Sig Block 42。
