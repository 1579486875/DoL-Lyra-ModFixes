# 第 12 轮报告：静态全绿，运行时是坏的

本轮的核心发现：之前各轮的检查几乎都是「静态 index + 对照汉化基线」，而玩家看到的是「运行时」内容——
ModI18N、TweeReplacer、maplebirch 都会在加载时再改一遍 passage 和 JS。
本轮建了「运行时导出」和「运行时验证门」，一次挖出 6 类只在运行时可见的问题，其中 4 类是我自己的构建脚本造成的。

## 三、构建与验证流程

- **先验后发**：`build.py` 改为签名后依次跑 REGRESS_ALL → validate → exec_verify → **RT_GATE**，任何一项失败都不归档、不覆盖 out/。旧流程先覆盖 out/ 再跑回归，失败只告警。本轮这个机制挡下了 3 个坏包。
- **RT_GATE（运行时验证门，新增）**：无头 Edge 加载整包，导出运行时全部 passage/widget/script，然后检查：
  G1 就绪；G2 模组补丁零错误；G3 运行时宏表达式可编译；G4 运行时宏结构不劣于 vanilla；G5 成就中文覆盖不低于基线；G6 新档开局、社交面板、服装店、钓鱼、#582/#583/#584 现场零红字。
- **`cdp_suite.js`** 会数页面里的 `.error` 元素。SugarCube 的宏错误是渲染进页面的，不抛异常，旧 `cdp_flow.js` 的「10 步 0 错误」看不见它们。
- **结构检查改为对照 vanilla 英文原版**（`scan_lib.struct_regressions`），并补上「无主闭合标签 / 不存在的闭合宏」两种错误。对照汉化基线只能说明「问题来自汉化包」，不能说明无害。
