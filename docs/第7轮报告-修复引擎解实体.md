## 二、根因：不是 passage，是**明文 JS 块被“解实体”**

### 2.1 现象

- 包能装、能启动，但页面一直转圈，CDP 等 1502 秒仍 `ready:false`
- 加载期日志两条：

```
[exception] SyntaxError: missing ) after argument list
[exception] SyntaxError: Unexpected string
```

### 2.2 定位过程

1. 抽 `index.html` 的 12 个明文 `<script>` 块，逐块 `node --check`
2. 两个块报语法错误：`script-sugarcube`（381 KB 引擎）与 webpack `BeforeSC2`（4.6 MB）
3. 与黄金基线 diff，第一处差异就在 HTML 实体映射表：

| | 黄金基线 | 坏包 |
|---|---|---|
| `_markupCharsMap` | `{"!":"&#33;",'"':"&quot;","#":"&#35;",…}` | `{"!":"!",'"':'"',"#":"#",…}` |
| `&quot;` 计数 | 7 | **0** |
| `&#\d+;` 计数 | 31 | **0** |

`'"':'"'` 让 JS 字符串的引号成对关系崩掉 → `Unexpected string`；webpack 块同因 → `missing )`。

### 2.3 关键判据（这次新学到的）

> **`&quot;` / `&#\d+;` 的计数可以当“解实体”的指纹。**
>
> - 整份 index：`&lt;`/`&gt;` 各 170 万条（passage 正文，转义形态，**正常**）
> - 明文 `<script>` 区：`&quot;` 应为 7、`&#\d+;` 应为 31
> - 若这两项归零，而 passage 数、`&lt;` 数都正常 → **只解了明文 JS 区**，正是本次事故

**为什么 98 项静态回归没抓到**：它们数 passage、数表、查字符串，不编译引擎 JS。
`C.sc_compile` 只编译 SugarCube 宏表达式，不碰 `<script>` 块。

### 2.4 修法（①保意图）

从黄金基线把这两个块**原样搬回**，其余内容一字不动：

```python
PAT = re.compile(r'<script\b([^>]*)>(.*?)</script>', re.S)
# 按块序号替换：#3 webpack BeforeSC2、#11 script-sugarcube
```

脚本：`work\CUR17_restore_engine.py`
校验：两块 md5 与基线一致、passage 仍 16088、`node --check` 全 OK。

## 三、附带修复：森林商店筛选器

**现象**（用户实测 + RT_GATE 复现）：

```
<<forestShop-main>>: <<if>> bad conditional expression in <<elseif>> clause (#1):
TypeError: Cannot read properties of undefined (reading 'includes')
```

**根因**：`forestShop-main` 内 3 处裸调 `$gwylanSeen.includes(...)`，新档 `$gwylanSeen` 未定义。

**修法（②兜底，只改调用点，不初始化变量）**：

- `$gwylanSeen.includes(` → `($gwylanSeen || []).includes(`（3 处）
- `slot?.type.includes("heavy")` → `slot?.type?.includes("heavy")`（1 处）

> 不写 `<<set $gwylanSeen to $gwylanSeen || []>>` 的原因：会让 `<<if $gwylanSeen>>` 从 false 变 true，
> 改变“是否见过格威岚”的语义。

脚本：`work\CUR22_fix_forest.py`
