## 一、问题

原版 DoL 与 BasicNeeds 是**两套独立的饥饿系统**：

| 系统 | 变量 | 刻度 |
|---|---|---|
| 原版 DoL | `$hunger` / `$thirst` | 0 – 2000 |
| BasicNeeds | `$BasicNeeds.hunger` / `.thirst` | 0 – 10000 |

两套互不同步：原版食物只补 `$hunger`，BasicNeeds 食物只补 `$BasicNeeds.hunger`，玩家看到的两条饥饿条会互相矛盾。

## 二、失败的三次尝试

| # | 路线 | 做法 | 结果 |
|---|---|---|---|
| 1 | **widget 层** | 在原版 `<<widget "hunger">>` 里插 `<<set $BasicNeeds.hunger ...>>` | ❌ 加载失败：`Cannot read properties of undefined (reading 'has')` |
| 2 | **JS 层（第一次）** | 改 BasicNeeds 的 `Ban-food.js`（`itemVol` 处）与 `Ban-needs.js`（`settle` 头） | ❌ 加载超时 1201 秒 |
| 3 | **JS 层（第二次）** | 同上，加 `try/catch` 与 `V.hunger !== undefined` 保护 | ❌ 同样超时 |

**根因判断**：
- 原版 `<<widget "hunger">>` 之外还有 **Remy Love 的同名 `<<widget "hunger">>`** 覆盖，插入后破坏 SugarCube 的 widget 注册；
- `Ban-food.js` 的 `injectFoodstuff` 作用域里 `V.hunger` 行为不可控，`settle` 每帧执行把异常放大成加载卡死。

## 三、成功方案：`</body>` 前的运行时钩子

**完全不改模组、不改 widget**，只在 index 的 `</body>` 前注入一段 `<script id="bn-hunger-sync-hook">`。

```js
(function () {
  if (window.__bnHungerSyncInstalled) return;
  window.__bnHungerSyncInstalled = true;
  var lastH = null, lastT = null;

  function V() {
    return (window.SugarCube && SugarCube.State) ? SugarCube.State.variables : null;
  }

  // 原版 -> BasicNeeds：只在原版值变化时同步（避免每帧覆盖 BasicNeeds 的进食）
  function syncToBn() {
    try {
      var v = V();
      if (!v || !v.BasicNeeds) return;
      if (typeof v.hunger === "number" && isFinite(v.hunger) && v.hunger !== lastH) {
        lastH = v.hunger;
        var h = Math.min(10000, v.hunger * 5);
        if (h > (v.BasicNeeds.hunger || 0)) v.BasicNeeds.hunger = h;
      }
      // thirst 同理
    } catch (e) {}
  }

  // BasicNeeds -> 原版：吃饱了就降低原版饥饿（只降不升）
  function syncToVanilla() {
    try {
      var v = V();
      if (!v || !v.BasicNeeds) return;
      var bn = v.BasicNeeds;
      if (typeof bn.hunger === "number" && isFinite(bn.hunger) && typeof v.hunger === "number") {
        var vh = Math.max(0, Math.min(2000, bn.hunger / 5));
        if (vh < v.hunger) { v.hunger = vh; lastH = vh; }
      }
      // thirst 同理
    } catch (e) {}
  }

  $(document).on(":passagedisplay", function () { syncToBn(); syncToVanilla(); });
  $(document).on(":passagerender", function () { syncToBn(); });
})();
```

### 关键设计

1. **`lastH` / `lastT` 游标**：`syncToBn` 只在原版值**变化时**才同步，否则它会把 BasicNeeds 的饥饿值一直拉回 `$hunger * 5`，**抵消掉 BasicNeeds 的进食效果**（这是第一版钩子踩到的坑）。
2. **`syncToVanilla` 回写后同步更新游标**：避免下一轮 `syncToBn` 又把值拉回去，形成振荡。
3. **全程 `try/catch` + `isFinite`**：任何异常都不会向上传播，不会影响加载。
4. **`State.variables` 动态获取**：存档切换后钩子仍然有效（不缓存旧对象）。

## 六、代价与边界

- **`$hunger` 与原版剧情的一致性**：`syncToVanilla` 会把原版 `$hunger` 压到 `bn.hunger / 5`，因此**只要 BasicNeeds 吃饱，原版也判定为饱**；原版剧情里的「饿到极限」事件不会在玩家吃饱时误触发。
- **BasicNeeds 的消化进度**：`syncToBn` 只在原版值变化时同步，不会每帧覆盖，消化系统的 `settle` 正常工作。
- **不碰任何模组文件**：Remy Love 的 `<<widget "hunger">>` 与 BasicNeeds 的原文件都保持原样。
